# 首字等待提醒维护说明

首字等待提醒回答的是「这一轮有几段等待达到了阈值」，不是「服务端排了多久」。请求记录中的 TTFT 是模型首字耗时；本地步骤的时间差只是估算。两者都无法单独区分服务端排队、模型预填充和网络延迟。

## 计时与归属

- **已发生的等待**：本轮请求有 TTFT 时优先用该值；没有对应 TTFT 时，可用 Planner（生成步骤）从创建到开始生成的时间差。请求与步骤关联明确时，TTFT 替换同一步骤的估算；没有关联时可能重复计数，不能仅凭时长相等去重。
- **正在等待**：优先从本轮待生成步骤的创建时间起算。没有这一步骤时，可从消息明确开始处理或上一步明确结束的时刻起算；没有可靠时间就不启动计时，不回退到消息入队时间。
- **停表与换轮**：本轮工具运行、流式输出或轮次终止时不累加实时等待。同一步骤已有 TTFT 或开始生成的时间，也不再计时。旧轮仍在运行时，不能仅凭界面显示 Working 就给新轮计时。下一条消息开始处理才切换统计范围。
- **子 Agent**：读取子对话自己的最近一次执行记录，不把父对话或上一次执行的等待加进来。实时计时只从有可靠创建时间、仍在等待首 token 的生成步骤起算。

黄色胶囊默认在单段等待 **达到** 30 秒时出现。`等待×2 40s` 表示本轮有两段达到阈值，其中正在等待的一段估计为 40 秒。`×2` 不是请求数，`40s` 也不是两段耗时的总和。

## 实现与回归

[server.mjs](../agy-capsule/sidecars/agy_capsule/server.mjs) 从会话 SQLite 快照读取请求与步骤，[metrics.mjs](../agy-capsule/sidecars/agy_capsule/metrics.mjs) 归属等待并选取实时起点，[ui.mjs](../agy-capsule/sidecars/agy_capsule/ui.mjs) 应用阈值并生成胶囊。

修改计时或归属时，运行 [request-alerts.test.mjs](../test/request-alerts.test.mjs)。它覆盖工具和流式输出停表、跨轮状态交错、排队消息开始处理，以及 TTFT 先于步骤状态更新或缺少请求输入索引的情况。

```sh
node --test test/request-alerts.test.mjs
```
